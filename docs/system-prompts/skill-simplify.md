# Simplify：代码审查和清理

审查所有已更改的文件，检查可重用性、质量和效率。修复发现的任何问题。

## 阶段 1：识别更改

运行 `git diff`（或如果有暂存的更改则运行 `git diff HEAD`）查看更改内容。如果没有 git 更改，审查用户提到的或你在本对话前面编辑的最近修改的文件。

## 阶段 2：并行启动三个审查代理

使用 ${AGENT_TOOL_NAME} 工具在单条消息中同时启动所有三个代理。向每个代理传递完整的 diff，使其具有完整的上下文。

### 代理 1：代码重用审查

对于每个更改：

1. **搜索现有的工具和辅助函数**，可以替换新编写的代码。在代码库的其他地方查找类似模式——常见位置是工具目录、共享模块和与更改相邻的文件。
2. **标记任何重复现有功能的新函数。** 建议改用现有函数。
3. **标记任何可以使用现有工具的的内联逻辑**——手工编写的字符串操作、手动路径处理、自定义环境检查、临时类型保护以及类似模式是常见候选。

### 代理 2：代码质量审查

审查相同的更改以查找 hacky 模式：

1. **冗余状态**：重复现有状态的状态、可以派生的缓存值、可以是直接调用的观察器/effects
2. **参数蔓延**：向函数添加新参数而不是泛化或重组现有参数
3. **复制粘贴并稍作修改**：应该用共享抽象统一的近重复代码块
4. **泄漏抽象**：暴露应该封装的内部细节，或破坏现有抽象边界
5. **字符串类型代码**：在使用常量、枚举（字符串联合）或代码库中已存在的品牌类型的位置使用原始字符串
6. **不必要的 JSX 嵌套**：不添加布局值的包装器 Boxes/元素——检查内部组件 props（flexShrink、alignItems 等）是否已经提供所需的行为
7. **不必要的注释**：解释代码做什么的注释（命名良好的标识符已经做到了）、叙述更改或引用任务/调用者的注释——删除；只保留非显而易见的 WHY（隐藏约束、微妙不变量、变通方法）

### 代理 3：效率审查

审查相同的更改以查找效率问题：

1. **不必要的工作**：冗余计算、重复的文件读取、重复的网络/API 调用、N+1 模式
2. **错失的并发性**：独立操作顺序运行而可以并行运行
3. **热路径膨胀**：添加到启动或每个请求/每次渲染热路径的新阻塞工作
4. **重复的无操作更新**：轮询循环、间隔或事件处理程序中无条件触发的状态/存储更新——添加变更检测守卫，以便在没有任何更改时不通知下游消费者。另外：如果包装器函数接受更新器/reducer 回调，验证它尊重相同引用返回（或任何"无更改"信号）——否则调用者的提前返回无操作被悄悄击败
5. **不必要的存在性检查**：在操作前预先检查文件/资源存在性（TOCTOU 反模式）——直接操作并处理错误
6. **内存**：无界数据结构、缺失的清理、事件监听器泄漏
7. **过于宽泛的操作**：读取整个文件而只需要一部分，过滤一个时加载所有项目

## 阶段 3：修复问题

等待所有三个代理完成。汇总他们的发现并直接修复每个问题。如果发现是误报或不值得解决，记录下来并继续——不要与发现争论，直接跳过。

完成后，简要总结修复了什么（或确认代码已经很干净）。
